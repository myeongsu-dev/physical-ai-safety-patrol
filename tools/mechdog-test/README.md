# MechDog 동작 시험 도구

02 기능정의서의 기능(F-01~F-13)과 「6. 기술 검증 항목」을 실제 로봇으로 반복 시험하고, 결과를 CSV로 남기는 도구입니다. 단위테스트가 아니라 로봇 동작 시험입니다.

## 구성

| 경로 | 내용 |
|---|---|
| `devices/dog/mechdog_test.py` | MechDog 본체에 올리는 MicroPython 프로그램 (BLE로 명령을 받음) |
| `devices/dog/sim_check.py` | 로봇 프로그램 셀프 체크 (가짜 Hiwonder 모듈로 PC에서 실행) |
| `app/index.html` · `app/main.js` | 시험 화면 (크롬·엣지, 웹 블루투스) |
| `app/devices/ble.js` | BLE 통신 (서비스 FFE0, 쓰기 FFE1, 알림 FFE2) |
| `app/core/` | 프로토콜 · 장치 모음(hub) · 실행기(runner) · 계산(metrics) · 결과 저장(results) |
| `app/tests/` | 시험 1개 = 파일 1개. 목록은 `tests/index.js` |
| `app/selfcheck.mjs` | 앱 셀프 체크 (가짜 로봇으로 시험 실행·판정까지) |
| `results/` | 저장한 CSV를 두는 곳 |

## 쓰는 법

1. **로봇에 프로그램 올리기**: Hiwonder Python Editor로 `devices/dog/mechdog_test.py`를 MechDog에 올립니다. 기본 앱으로 돌아가려면 원래 `Blue.py`(`01_docs/mechdog/07_동작편집/7.6 …`)를 다시 올립니다.
2. **화면 열기**: 이 폴더에서 아래를 실행한 뒤 크롬·엣지로 `http://localhost:8799`를 엽니다. 웹 블루투스는 `localhost`나 https에서만 동작합니다. 아이폰 사파리는 지원하지 않습니다.
   ```
   python -m http.server 8799 --bind 127.0.0.1 --directory app
   ```
3. **로봇 연결 → 시험 고르기 → 조합 확인 → 실행**: 로봇이 지원하지 않는 시험은 이유와 함께 막혀 있습니다. 안내창이 뜨면 준비하고 확인을 누르고, 손으로 잰 값을 입력합니다.
4. **정지**: 화면 오른쪽 위 빨간 버튼이나 스페이스바를 누릅니다. 블루투스 연결이 끊겨도 로봇은 바로 멈추고, 이동 명령은 한 번에 최대 15초까지만 갑니다.
5. **저장**: 끝나면 `요약 CSV`(실행 1회 = 1줄)와 `원시 CSV`(스트림·이벤트 전부)를 받아 `results/`에 넣습니다. 브라우저를 닫으면 결과가 사라집니다.

## 시험 묶음

| 묶음 | 내용 | 필요한 것 |
|---|---|---|
| A 주행 기초 | 제자리 회전 · 걸으며 회전 반경 · 직진 흔들림 · 걸음 설정별 속도 · 하중 보행 · 배터리 지속 | 본체 (A3는 비전 모듈) |
| B 바닥 카메라 | 보는 거리 · 선 색별 인식 · 색 띠 마커 인식률(F-02) · 선 따라 3바퀴(F-01) · 바닥 물건(F-04) | 기본 비전 모듈 (선: line_patrol 펌웨어, 색: color_detection 펌웨어) |
| C 초음파 · 막힘 | 막힘 앞 정지(F-03) · 거리별 정확도 · 걸으며 측정 · 빈 통로 오탐 · 치운 뒤 재출발(F-09) | 본체 |
| D LED 표시 | 화살표 · ✕ 보이는 거리(F-12) | LED 도트 매트릭스 |
| E~I | 머리 카메라·온도, 온보드 AI, 관제·통신, 다중 협업, 시연 리허설 | 장치가 생기면 열림 (`tests/planned.js`) |

## 통신 형식

기본 앱과 같은 `CMD|…|$` 형식입니다. 명령에는 `CMD|명령|ok|$`로, 실패하면 `CMD|!|명령|이유|$`로 답합니다.

| 명령 | 뜻 |
|---|---|
| `V` | 정보 → `CMD|V|버전|명령,…|숫자 채널,…|이벤트 채널,…|$` |
| `M|보폭|각도|ms` | 이동 (`mechdog.move`), ms 뒤 정지하며 `E|t|done|1` |
| `F|보폭|각도|ms` | 선 따라가기 (선 x가 60보다 작으면 왼쪽, 100보다 크면 오른쪽으로 꺾음) |
| `U|보폭|정지cm|재개cm|ms` | 초음파 정지 걷기: 정지 거리 안이 3번 연속이면 멈추고 `E|t|stop|거리`, 재개 거리 밖이면 다시 걷고 `E|t|resume|거리` |
| `G|들기|딛기|높이` | 걸음 설정 (`set_gait_params`) |
| `S` · `P` | 정지 · 기본 자세 |
| `L|모드|값` | LED (`num`·`bright`는 확인된 기능, `text`·`char`·`clear`는 펌웨어에 함수가 있을 때만) |
| `C|색` | 선 따라가기 색 (`YELLOW` 등 비전 모듈 상수 이름) |
| `T|간격ms|채널,…` | 측정값 스트림 → `CMD|D|t|값…|$` (숫자 채널), 이벤트 채널은 바뀔 때만 `CMD|E|t|채널|값|$`. 간격 0이면 끔 |
| `6` | 배터리 (기본 앱과 같음) |

채널: `bat` 전압 · `sonar` 초음파 · `roll` · `pitch` IMU · `line` 선 x(0~160, 안 보이면 -1) · `color` 인식한 색 번호(이벤트).

## 시험 추가하는 법

1. `app/tests/`에서 비슷한 파일을 복사해 `묶음문자+번호_이름.js`로 만듭니다.
2. 아래 항목을 채웁니다.
   - `needs`: 필요한 장치·명령·채널
   - `record`: 기록할 채널과 간격
   - `steps(조합, 회차)`: 단계 목록 (`{ do: [장치, 명령, …값], wait }`, `{ ask }`, `{ until: [장치, 이벤트] }`)
   - `manual`: 손으로 잴 값
   - `truth`: 정답 입력 (인식 정확도 시험)
   - `metrics`: 자동 계산
   - `success` · `pass`: 판정 (문서의 합격 기준)
3. `tests/index.js`에 한 줄 추가합니다.

새 센서나 동작이 필요하면 장치 프로그램의 `COMMANDS` · `CHANNELS` · `EVENTS` 표에 함수 하나를 등록합니다. 새 장치(XIAO, Pi 5, 서버)는 `app/devices/`에 `ble.js`와 같은 모양(`connect(onChunk, onClose) → { name, write, close }`)의 통신 파일을 만들고, 장치 쪽도 같은 `CMD` 형식과 `V` 응답을 따르게 합니다.

## 실기에서 먼저 확인할 것

- `read_angle()`이 [롤, 피치] 순서인지, `getDistance()`가 cm인지(기본 앱이 ×10으로 mm를 만듦), `Battery_power()`가 mV인지
- `line_follow()`가 검정 선을 읽는지 (공식 예제는 노란 선) → B2로 확인
- `move(0, 각도)`가 제자리 회전인지 → A1로 확인
- LED의 `text`·`char` 지원 여부, 도트 매트릭스 포트(`Digitaltube()` 기본값) → D1로 확인
- 20바이트가 넘는 명령(`T|100|sonar,roll,pitch,bat`)을 로봇이 이어 받는지 → 안 되면 채널 이름을 줄임

## 셀프 체크

```
node app/selfcheck.mjs              # 앱: 프로토콜·계산·실행기·판정
python -I devices/dog/sim_check.py  # 로봇 프로그램: 명령·자동 정지·초음파 정지 규칙
```

# Pi 5 보조배터리 시험 도구

보조배터리 하나로 라즈베리 파이 5가 AI 추론까지 버티는지 판정하고, 몇 분 쓸 수 있는지 잽니다. 보조배터리는 Pi에만 전기를 주므로 책상 위에서 **Pi + Pi에 꽂히는 것(XIAO 카메라)** 만 놓고 시험합니다.

## 무엇으로 실제 부하를 대신하나

| 실제 (나중) | 시험에서 | 이유 |
|---|---|---|
| 안전모 모델 | `yolo11n.pt` 기본 모델 | 같은 nano 크기라 CPU·전기 쓰는 양이 같음 |
| XIAO 영상 추론 | ultralytics 안의 `bus.jpg` 반복 추론 | 계산량은 같음. XIAO는 꽂아서 전기를 먹게 함 |
| 화재 의심 때 모델 2개 | 추론 프로세스 2개 동시 | 가장 무거운 순간 |
| 온도센서 GY-906 | 없이 | 2mA라 결과에 영향 없음 |

프레임 제한 없이 계속 추론하므로 실제 순찰(카메라 15장/초)보다 무겁습니다. 사용 시간은 보수적으로 나옵니다.

## Pi 준비 (전날, 인터넷 되는 곳에서 한 번)

`config.txt`와 EEPROM 설정은 바꾸지 않습니다. 실제 로봇과 같은 조건이어야 판정이 맞습니다.

1. Raspberry Pi OS 64-bit (bookworm)를 깔고 SSH·Wi-Fi를 켭니다. 쿨러를 답니다.
2. `sudo apt update && sudo apt install -y git tmux`
3. 저장소를 받습니다.
   ```bash
   git clone https://github.com/myeongsu-dev/physical-ai-safety-patrol.git
   cd physical-ai-safety-patrol && git switch tools/pi-power-test
   ```
4. `python -m venv ~/potent && . ~/potent/bin/activate && pip install ultralytics` (torch 포함 수백 MB라 오래 걸립니다)
5. XIAO를 Pi USB에 꽂고 `python tools/pi-power-test/power_test.py check`. 모델을 자동으로 받고, `점검 통과`가 나와야 합니다.

## 현장 순서

SSH 창을 닫아도 계속 돌도록 `tmux` 안에서 실행합니다(`tmux` → 끊기면 `tmux attach`). 매번 저장소 맨 위에서 venv를 켭니다(`. ~/potent/bin/activate`).

1. **어댑터 기준 (15분)**: 정품 27W 어댑터나 노트북 충전기로 켜고
   `python tools/pi-power-test/power_test.py run --label 어댑터 --adapter --cable 정품`
2. **보조배터리마다 (15분씩)**: 완충한 배터리로 바꿔 꽂으면 Pi가 다시 켜집니다. 그다음
   `python tools/pi-power-test/power_test.py run --label 명수30000 --capacity 30000 --cable "C to C 30cm"`
3. **실제로 얹을 후보 하나만 끝까지 (1~2시간)**: 꺼질 때까지 재서 사용 시간을 실측하고, 다른 배터리의 예상 시간도 이 값으로 보정합니다.
   `python tools/pi-power-test/power_test.py run --label 앵커5000 --capacity 5000 --cable "C to C 30cm" --drain`
   꺼지면 어댑터로 다시 켜고 4번으로 넘어갑니다.
4. **결과 보기**: `python tools/pi-power-test/power_test.py report`. 배터리별 판정 표가 나오고 `results/*_진단.txt`를 새로 씁니다.

- 중간에 멈출 때는 **Ctrl+C**. 전원을 뽑으면 '전원 꺼짐(사용 불가)'으로 판정됩니다.
- 배터리 겉에 "정격용량 ○○mAh (5V)"가 있으면 `--capacity` 대신 `--rated5v ○○`을 넣습니다. 더 정확합니다.
- USB-C 전류 측정기가 있으면 평상 구간에서 본 W를 `--watts 6.2`처럼 넣습니다. 가장 정확합니다.
- 필요한 사용 시간은 `--need 분` (기본 60분)이고, `--drain` 판정에만 씁니다.

한 회차는 **대기 2분 → 평상(추론 1개) 8분 → 최대(추론 2개) 5분**이고, `--drain`이면 이어서 평상 부하로 꺼질 때까지 갑니다. 2초마다 `results/<이름>_<시각>.csv`에 한 줄씩 바로 저장하므로, 전원이 꺼져도 마지막 줄이 꺼진 시각입니다.

## 판정

배터리를 잘못 버리거나 잘못 쓰지 않도록 이렇게 정했습니다.

- **사용 불가**는 확실한 증거가 있을 때만 냅니다. Pi 펌웨어가 남긴 전압 부족 기록, 재부팅으로 확인된 전원 꺼짐, 끝까지 잰 시간 부족이 증거입니다.
- **사용 가능**은 부하가 실제로 걸린 채 15분을 다 채웠을 때만 냅니다.
- 배터리 탓인지 모르는 문제는 **재시험**입니다.
- 전압 부족은 2초마다 재는 전압값이 아니라 `vcgencmd get_throttled`의 "부팅 뒤 한 번이라도" 비트로 봅니다. 그래서 측정 사이의 순간 저하도 잡힙니다.

| 결과 | 조건 (위에서부터 먼저 맞는 것) |
|---|---|
| 재시험 | 다른 이름의 회차와 같은 부팅 중에 기록됨 (배터리를 바꾸면 반드시 재부팅되므로 이름을 잘못 붙인 것) |
| 시험 무효 | 어댑터 회차인데 전압 부족 → 어댑터·케이블을 바꿔 기준부터 다시 |
| 사용 불가 | 전압 부족 기록 (시작 때 이미 있으면 "이 배터리로 부팅하다 발생") |
| 사용 불가 | 끝 표시 없이 끊기고 Pi가 다시 부팅됨 = 전원이 꺼짐 (대기 구간이면 자동 꺼짐 배터리일 수 있음) |
| 사용 불가 | `--drain` 실측 시간 < `--need` (방전 끝 무렵 전압 부족이 나면 그 시점까지만 셈) |
| 재시험 | 끝 표시 없음 + 같은 부팅 = 프로그램만 멈춤 (SSH 끊김 등) |
| 재시험 | 15분을 다 못 채움, 측정 실패 10% 넘음, 추론이 안 돌았거나 멈춤 (부하가 덜 걸리면 배터리가 좋아 보이므로) |
| 재시험 | 80℃ 이상이거나 전압 부족 없이 속도를 낮춤 = 발열 → 쿨러 확인 |
| 재시험 | XIAO만 USB에서 사라짐 → 다시 꽂고 재시험, 또 끊기면 USB 전원 부족 의심 |
| 기준 완료 | 어댑터 회차가 정상으로 끝남 |
| 사용 가능 | 위에 해당 없음 |

판정은 **배터리 + 케이블 조합** 기준입니다. 불가가 나오면 굵고 짧은 다른 케이블로 한 번 더 해 보고 버립니다.

## 사용 시간

사용 가능한 배터리마다 "평상 약 X~Y, 최대 부하 약 Z"를 범위로 냅니다. 범위는 보조배터리 변환 효율 75~90%를 반영한 것입니다.

| 방법 | 언제 | 정확도 |
|---|---|---|
| 실측 | `--drain`으로 꺼질 때까지 잰 회차 | 가장 정확 |
| 측정기 | `--watts`를 넣은 회차 | 정확 |
| 보정됨 | 같은 Pi로 끝까지 잰 회차가 하나라도 있을 때. 그 실측으로 소비 전력 추정값을 바로잡음 | 쓸 만함 |
| 보정 전 | 위가 다 없을 때. Pi 내부 전력만 더한 값이라 USB로 내주는 전기와 변환 손실이 빠짐 | **실제보다 길게 나올 수 있음** |

사용 시간은 참고값이고, `--drain` 실측이 `--need`보다 짧을 때만 판정에 들어갑니다.

## 진단서 (`results/*_진단.txt`)

회차마다 하나씩 생깁니다. 판정과 이유, 다음에 할 일, 사용 시간, 최저 전압, 어댑터 대비 추론 속도가 들어갑니다. 근거(처음 문제가 생긴 시각·구간·전압·온도)와 시험 조건도 함께 적습니다. 전원이 꺼진 회차는 그 자리에서 쓸 수 없으므로, 다시 켠 뒤 `report`가 씁니다. 점검에서 막히면 `<이름>_<시각>_진단.txt`에 무엇이 안 됐고 어떻게 고치는지 남깁니다.

## 셀프 체크

`python tools/pi-power-test/power_test.py selfcheck`는 Pi 없이 PC에서 돌아갑니다. 위 판정 표의 줄마다 가짜 기록을 만들어 판정이 맞는지 확인하고, CI(`tools/check.sh`)도 PR마다 이걸 돌립니다. 판정 규칙을 고치면 셀프 체크도 함께 고칩니다.

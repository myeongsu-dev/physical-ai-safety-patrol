# 비전 모듈 펌웨어 · 박명수

MechDog 바닥 카메라(ESP32-S3 비전 모듈, 카메라 GC2145)에 올리는 펌웨어 `patrol_cam`과 굽기·영상 보기 도구입니다.

| 하는 일 | 언제 |
|---|---|
| 검은 선 찾기 → MechDog 보드가 I2C로 읽음 | 항상 |
| 영상 보내기 (USB 시리얼 또는 Wi-Fi, 찾은 선 상자를 그려서) | `view.py`를 켠 동안만 (디버깅용) |

Pi에서 `view.py`를 켜고 PC 브라우저로 봅니다. 영상은 모듈 USB가 Pi에 꽂혀 있으면 USB로, 없으면 Wi-Fi로 받습니다. 주행할 때는 케이블이 바닥에 끌려 방향이 틀어지므로 USB를 뽑고 Wi-Fi로 봅니다.

## 영상 보기

```
python firmware/vision/view.py [포트] [--url URL] [--thr N]
```

- 브라우저에서 `http://<view.py를 켠 기기 주소>:8090`을 엽니다. 초록 상자가 찾은 선, 회색 줄이 구역 경계입니다. 위쪽 표시에 받는 길(USB · Wi-Fi)과 초당 장 수가 나옵니다.
- 켜는 동안만 영상을 보내고 Ctrl-C로 끄면 멈춥니다. 선 찾기는 영상과 상관없이 계속 돕니다.
- 받는 순서: USB 포트가 있으면 USB, 없으면 Wi-Fi(`--url`, 기본 `.env`의 `VISION_URL` 또는 `http://patrol-cam.local/stream`), 둘 다 없으면 "모듈 연결 없음"으로 기다립니다. 켜 둔 채 꽂고 뽑아도 1초 안에 바뀝니다.
- 초당 약 9장입니다(모듈이 JPEG를 만드는 속도). Wi-Fi로 받는 동안 모듈은 USB 쪽 영상을 끕니다. 둘을 같이 보내면 Wi-Fi가 막힘(초당 5장, 핑 279 ms → Wi-Fi만 8.5장, 36 ms, 2026-11-26).
- `--thr N`: 검정 기준 밝기(1~254, 처음 160). 바닥까지 검정으로 잡히면 낮추고, 테이프를 놓치면 올립니다. 모듈에 저장됩니다. USB로만 됩니다.
  - 처음 값 160은 집 바닥에서 임시로 잰 값입니다. 미션맵 바닥·테이프·조명에서 다시 재서 `patrol_cam.ino`의 `THR_DEFAULT`를 고쳐야 합니다.
- 포트를 안 주면 `.env`의 `VISION_PORT`를 씁니다. 포트는 기기마다 다르니 `python -m edge.hwcheck ports`로 찾습니다. 비전 모듈과 MechDog 보드는 같은 CH340 칩이라 Pi에서는 꽂은 USB 자리로 정해지는 `/dev/serial/by-path/...` 이름이 안 헷갈립니다.

### Wi-Fi 설정 (모듈마다 한 번)

모듈 USB를 꽂고 직접 터미널에서 실행합니다. 비밀번호는 화면과 기록에 남지 않고 모듈에만 저장됩니다.

```
python firmware/vision/view.py --wifi
```

- 모듈에 보이는 Wi-Fi 목록이 나오면 이름과 비밀번호를 넣습니다. `Wi-Fi: 172.30.1.xx`가 나오면 붙은 것입니다.
- Wi-Fi는 4개까지 저장됩니다(집 · 휴대폰 핫스팟 · 시연장 …). 넣을 때마다 목록 맨 앞에 들어가고, 이름이 같으면 비밀번호만 바뀝니다. 이름을 비우면 모두 지웁니다. 모듈은 저장한 Wi-Fi를 하나씩 8초씩 차례로 시도합니다.
- 모듈(ESP32-S3)은 2.4GHz만 됩니다. 같은 공유기의 2.4GHz에 붙이면 5GHz에 붙은 Pi · PC와 같은 내부망이라 그대로 보입니다. 학교 · 공공 Wi-Fi는 기기끼리 통신을 막거나(클라이언트 격리) 로그인 페이지가 있어 안 되는 경우가 많으니, 밖에서는 휴대폰 핫스팟(2.4GHz)에 Pi와 모듈을 같이 붙입니다.
- 모듈 이름: USB 시리얼(115200)에 `NAME patrol-cam-a`처럼 보내면 저장되고 다시 켜면 적용됩니다(영문 소문자 · 숫자 · `-`, 24자까지, 기본 `patrol-cam`). 로봇마다 다르게 정하고 Pi `.env`에 `VISION_URL=http://patrol-cam-a.local/stream`을 적습니다. 같은 Wi-Fi에 같은 이름이 여럿이면 어느 모듈이 잡힐지 모릅니다. 이름(mDNS)이 안 잡히는 망이면 `VISION_URL`에 주소를 적습니다. `INFO`에 `name`과 저장한 Wi-Fi 수 `nets`가 나옵니다.
- 20초 동안 저장한 Wi-Fi 어디에도 못 붙으면 모듈이 모듈 이름으로 Wi-Fi를 직접 띄웁니다(`INFO`에 `wifi=ap:192.168.4.1`). 노트북 · 휴대폰으로 그 Wi-Fi에 붙어 `http://192.168.4.1/stream`으로 영상을 보거나 Wi-Fi로 굽습니다. 띄운 동안에도 30초마다 저장한 Wi-Fi를 다시 시도하고(그때 붙어 있던 기기가 잠깐 끊김), 붙으면 끕니다. 비밀번호는 `APPASS <8자 이상>`(비우면 열린 Wi-Fi), 아예 안 띄우려면 `AP 0`. Pi는 서버와 쓰는 Wi-Fi가 있어 모듈이 띄운 Wi-Fi에 같이 붙지 못하니, 주행 중 Pi로 영상을 받는 용도는 아닙니다.
- 모듈은 `/stream`에 한 곳만 붙일 수 있습니다. 여러 사람이 볼 때는 Pi의 8090으로 봅니다.
- USB를 뽑고(I2C 선 전원만) Wi-Fi 영상이 초당 1~2장으로 떨어지면 송신 세기를 낮춥니다. 모듈 USB 시리얼(115200)에 `TXP 34`를 보내면 8.5 dBm으로 저장됩니다(0.25 dBm 단위, 8~84, 기본 78 = 19.5 dBm). 2026-11-27: 19.5 dBm에서 초당 1.3장 · 핑 28~138 ms → 8.5 dBm에서 초당 9장 · 핑 11~30 ms. 최대 세기 송신 순간 전류를 I2C 전원이 못 대는 것으로 봅니다. `INFO`에 `rssi`(신호 세기)와 `txp`가 나옵니다.

### Wi-Fi로 굽기 (USB 없이)

모듈에 열쇠를 넣어 둔 뒤에는 USB 없이 Wi-Fi로 굽습니다. 열쇠가 없는 모듈은 Wi-Fi 굽기를 받지 않습니다.

1. 모듈마다 한 번, USB 시리얼로 `OTAKEY <열쇠>`(32자까지)를 보내고 같은 값을 Pi `.env`의 `VISION_OTA_KEY`에 적습니다. `OTAKEY`만 보내면 지웁니다.
2. 굽기: `view.py`를 먼저 끕니다(모듈 웹 서버는 한 번에 요청 하나라 영상을 받는 동안은 굽기가 시작되지 않음).

```
curl -H "X-Key: $VISION_OTA_KEY" --data-binary @firmware/vision/patrol_cam/build/patrol_cam.ino.bin http://patrol-cam.local/update
```

- 굽는 파일은 `build.py`가 만든 앱 파일 `patrol_cam/build/patrol_cam.ino.bin`입니다(저장소의 `patrol_cam.bin`은 0x0부터 굽는 통 파일이라 안 됨).
- 새 펌웨어는 비어 있는 칸에 받고 검증이 끝나야 바꿔 켭니다. 중간에 끊기면 원래 펌웨어로 켜집니다. 1 MB에 약 10초, 끝나면 `ok`를 주고 다시 켜집니다. 저장해 둔 Wi-Fi · 기준 밝기 · 송신 세기 · 열쇠는 그대로입니다.

## 출발 전 카메라 각도 맞추기

카메라 각도는 경첩을 손으로 꺾어 맞춥니다. 주행 전에 한 번 맞춥니다.

조건:
- 로봇 앞 30 cm 이상이 곧은 테이프 구간. 코너 · 테이프 끝 · 찢어진 곳이 화면에 들어오지 않게 합니다.
- 로봇을 테이프 가운데에 테이프와 나란히 둡니다. 영상에서 테이프가 화면 가운데 위아래로 지나가야 합니다.
- 주행할 때와 같은 상태: 서 있는 자세, Pi · 배터리를 다 얹고 전원을 켠 채로. 무게로 몸이 기울면 각도가 달라집니다.
- 평평한 바닥, 테이프 위에 그림자 · 손 · 자 같은 검은 물건이 없게. 초록 상자가 테이프에 맞게 잡혀야 합니다.

순서:
1. `view.py`를 켜고 브라우저로 `http://<Pi 주소>:8090`을 엽니다. 인터넷은 필요 없습니다(three.js와 3D 모델이 `web/`에 있음).
2. "카메라 각도 맞추기"의 시작을 누릅니다. 누른 동안만 각도를 재고, 판정과 MechDog 옆모습(카메라와 시야가 지금 각도로 움직임)이 나옵니다.
3. 판정이 `좋음`이 될 때까지 경첩을 조금씩 꺾습니다. `너무 멀리 봄`이면 모듈 아래 끝을 뒤로 접고, `발 앞만 봄`이면 앞으로 세웁니다. 몇 도 움직일지도 나옵니다.
4. `좋음`이 2~3초 그대로면 손을 떼고 끝내기를 누른 뒤 출발합니다.

옆모습은 CAD 모델(`web/mechdog.glb`, `07_corp-project/cad` 빌드 결과 복사본)이라 높이가 실물과 조금 다릅니다. CAD를 다시 빌드하면 이 파일도 바꿔 넣습니다.

판정은 먼 구역·가운데 구역 줄마다 잰 테이프 폭이 위로 갈수록 줄어드는 기울기로 지평선 위치를 찾고, 거기서 렌즈가 아래로 꺾인 각도를 구합니다. 테이프 폭·렌즈 높이와는 상관없고, 화면에 지금 각도를 같이 보여 줍니다. 목표는 아래로 20° ± 1°입니다(`view.py`의 `AIM_DEG`). 이때 가운데 구역은 렌즈 앞 약 11 cm, 바닥 폭 약 6.5 cm를 봅니다. 카메라 시야는 세로 25° · 가로 33°, 렌즈 높이는 3.7~4.1 cm입니다(바닥에 자를 놓고 두 자세로 잰 값, `AIM_F`). 표시 각도는 1~2° 오차가 있습니다. "바닥 몇 cm 앞"은 같은 화면에서 테이프 폭(`AIM_TAPE_CM`, 지금 길은 18~19 mm)으로 잰 렌즈 높이로 계산합니다. 테이프가 화면 끝에 닿거나 화면에 테이프 없이 바닥만 보이면 `테이프가 안 보임`이 나옵니다. 자체 확인은 `python firmware/vision/view.py --selftest`로 합니다.

## MechDog 보드가 읽는 값

Hiwonder 비전 모듈과 같은 I2C 형식(주소 `0x53`)이라 보드 라이브러리 `cam.line_follow(cam.BLACK)`가 그대로 읽습니다.

- 화면을 위·가운데·아래 3구역으로 나눠 아래(발 바로 앞) → 가운데 → 위 순서로 검정 띠를 찾습니다. 아래 구역은 바로 전 장의 아래 구역 위치에서 40칸(`JUMP_MAX`) 안의 띠를 고릅니다. 가운데 · 위 구역은 바로 아래 구역 띠와 가로 범위가 겹치거나 6칸(`TOUCH_GAP`) 안으로 맞닿은 띠만 같은 선으로 봅니다(가운데 구역이 없으면 위 구역은 아래 구역과 40칸). 지금 밟는 선에서 이어지는 선만 따라가고 옆 트랙으로 넘어가지 않게 하면서, U자처럼 위 구역 테이프가 옆으로 누워 띠가 넓게 퍼져도 버리지 않게 하려는 것입니다(가운데끼리 거리로 보던 때는 버려서 곡선을 미리 못 봄, 2026-11-27 주행 영상). 기준이 없으면(처음, 0.5초 넘게 놓친 뒤) 가장 굵은 띠입니다. 검정 기준은 구역의 가장 어두운 쪽 40% 밝기(`thr`가 상한)라 테이프 가장자리 흐림 · 그림자를 덜 잡습니다.
- `0xB0`을 읽으면 위·가운데·아래 구역 7바이트씩 21바이트를 줍니다(보드 `main.py`가 씀). 레지스터 번호를 먼저 따로 써야 합니다. 이어서 읽으면(`readfrom_mem`) 지난 레지스터 값이 옵니다.
- Hiwonder 형식 `0xA8`(위)·`0xA9`(가운데, 못 찾으면 아래)도 그대로 둡니다.
- 각 7바이트 `[ID 5, 중심x, 중심y, 좌상x, 좌상y, 우하x, 우하y]`, 좌표는 160x120 기준(가운데 x=80). 못 찾으면 모두 0.
- 다른 레지스터(빨강·노랑 등 색, 얼굴)는 0입니다.

## 굽기

```
pip install esptool
python firmware/vision/flash.py [포트]
```

- 저장소에 빌드해 둔 `patrol_cam.bin`을 굽습니다. 빌드 도구가 없어도 됩니다.
- 포트를 안 주면 `.env`의 `VISION_PORT`. `DOG_PORT`와 같은 포트를 주면 굽지 않고 멈춥니다(MechDog 보드가 재시작되어 로봇이 주저앉음).
- 주소 `0x0`, 460800, 80MHz, DIO로 굽습니다(Hiwonder 안내와 같음). 구우면 저장해 둔 기준 밝기와 Wi-Fi 설정도 지워집니다(Wi-Fi는 `--wifi`로 다시 넣음).
- Hiwonder 공장 펌웨어로 되돌릴 때: `--bin <Hiwonder 펌웨어.bin>`. 파일은 Hiwonder가 제공하는 MechDog 자료의 비전 모듈 펌웨어 폴더에 있습니다.

## 고친 뒤 빌드

`patrol_cam.ino`를 고친 사람만 합니다. `arduino-cli`와 ESP32 보드 패키지(`arduino-cli core install esp32:esp32`, 3.x)가 필요합니다.

```
python firmware/vision/build.py
```

`firmware/vision/patrol_cam.bin`이 새로 만들어집니다. 소스와 함께 커밋해서 팀원은 빌드 없이 굽게 합니다.

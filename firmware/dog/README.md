# MechDog 보드 프로그램 · 박명수

MechDog 제어 보드(ESP32 · MicroPython)에 올리는 프로그램입니다. 몸으로 하는 일과 즉시 반응을 맡습니다.

| 하는 일 | 기능 |
|---|---|
| 선 따라가기, 색 띠 마커 읽기 | F-01 · F-02 |
| 초음파 막힘 정지 · 재개 | F-03 · F-09 |
| LED 화살표·✕, 음성 재생 (MP3 모듈) | F-12 · F-06 |
| 배터리 전압 보고 | F-11 |
| Pi가 2초 넘게 조용하면 정지 + LED 오류 | 안전 |

- 입력·출력: Pi 5와 USB 시리얼 `CMD|…|$` ([docs/protocol.md](../../docs/protocol.md) 1절)
- 프로그램: `main.py`. 시험 도구의 `mechdog_test.py`(BLE)와 명령 처리가 같고, USB 시리얼(REPL과 같은 UART, 115200)로 받습니다. `A`(음성), `L|arrow|left·right·up·x`(LED에 `<` `>` `^` `X` 글자), 2초 감시(멈추고 LED에 `E`)가 더해졌습니다.
- 셀프 체크: `python firmware/dog/sim_check.py` (가짜 Hiwonder 모듈로 PC에서, CI도 돌림)
- `main()`은 스레드가 아니라 파일 맨 끝에서 직접 돕니다. 파일이 끝나면 REPL이 켜져 Pi 명령을 가로채기 때문입니다.
- 올리기 (PC·Pi 같음): `python firmware/dog/upload.py [포트]`. 포트를 안 주면 `.env`의 `DOG_PORT`를 쓰고, 모르면 `python -m edge.hwcheck ports`로 찾습니다.
  - `edge.agent`가 포트를 쓰고 있으면 올리지 않고 멈춥니다. 에이전트를 멈추고 다시 합니다.
  - 다 올린 뒤 `main.py`가 `V`에 답하는 것까지 확인합니다.
  - 보드를 재시작하지 않고 `main.py`를 바꿔 그 자리에서 다시 실행합니다. 이전 파일은 보드에 `main_prev.py`로 남습니다.
  - 보드가 재시작되면 서보 힘이 빠져 로봇이 주저앉습니다(배 쪽 배터리에 충격). `mpremote`는 포트를 열 때 CH340 보드를 재시작시키고 올린 뒤 `reset`도 하므로 쓰지 않습니다.
- 처음 올릴 때(공장 앱이나 시험 도구가 돌고 있을 때)만 `mpremote`를 씁니다. 그 프로그램들은 시리얼을 스레드에서 읽어서 `upload.py`의 Ctrl-C로 멈추지 않습니다. 로봇을 눕힌 채 합니다:
  ```
  mpremote connect <포트> resume exec "import os; os.rename('main.py','main_off.py')"
  (보드 전원을 껐다 켬)
  mpremote connect <포트> resume fs cp firmware/dog/main.py :main.py
  mpremote connect <포트> resume reset
  ```
  `resume`을 빼면 소프트 리셋에서 보드가 죽었다가 다시 켜집니다. `could not enter raw repl`이 나면 부팅이 끝난 뒤 한 번 더 합니다.
- Pi(`edge/dog_link.py`)와 `upload.py`는 포트를 열어도 보드가 재시작되지 않게 엽니다. Windows는 열기 전에 DTR·RTS를 끄고, Linux는 커널이 켠 그대로 둡니다(열고 나서 하나씩 끄면 그 사이에 리셋됨). 둘 다 실기에서 확인했습니다.

## 검은 선 읽기

미션맵 선은 검은 테이프입니다. `main.py`는 `cam.line_follow(cam.BLACK)`으로 비전 모듈의 검정 레지스터(`0xA8` 위 구역, `0xA9` 가운데 구역)를 읽습니다. 위치 표식은 ArUco를 먼저 시험하므로 다른 색은 읽지 않습니다.

- 비전 모듈에는 우리 펌웨어 `firmware/vision/patrol_cam`을 굽습니다. Hiwonder 공장 펌웨어는 검정을 못 찾습니다. 굽기·영상 보기·기준 밝기 맞추기는 [firmware/vision/README.md](../vision/README.md).
- `line` 값은 선 중심 x(0~159, 가운데 80)입니다. 로봇에 가까운 가운데 구역을 먼저 쓰고, 없으면 위 구역, 둘 다 없으면 -1입니다.
- 선 따라가기(`F|보폭|최대 각도|ms`)의 목표는 영상에서 선이 가운데에 오는 것입니다(테이프가 조금 휘어도). 바닥 카메라 세 구역(아래 · 가운데 무게 1, 위 무게 0.5)의 선이 가운데에서 비켜난 거리(cm)의 가중 평균을 오차로 삼아, 비례해서 꺾고 같은 쪽으로 오래 비켜나 있으면 쌓아서 더 꺾습니다(한쪽으로 쏠려 걷는 것 보정). 걸을 때 머리(카메라)가 걸음마다 좌우로 흔들리므로 오차와 도는 속도는 한 걸음(0.7초) 평균을 씁니다. IMU 자이로로 도는 속도를 눌러 출렁임을 줄입니다. 왼쪽이 +각도이고 최대 각도에서 자릅니다. 보폭은 바꾸지 않습니다. 가장자리에 가까운 점일수록 무게를 더 크게 둬서, 곡선에서 가까운 점이 빠져나가기 전에 꺾습니다. 걸으며 돌 수 있는 원보다 좁은 곡선(U자 등)에 대비해, 한 걸음 평균으로 선이 1.5 cm 넘게 비켜나면 앞으로 가지 않고 제자리에서 선 쪽으로 돌고(각도 40), 지금 값이 0.4 cm 안으로 오거나 반대쪽으로 넘어가면 바로 다시 걷습니다(`PIVOT_*`). 선을 못 찾으면 0.6초는 걸으면서 마지막으로 본 선 쪽으로 최대 각도로 꺾고, 그래도 없으면 제자리에서 그쪽으로 돌며 찾습니다(보폭 0, 각도 40). 90° 돌거나 8초 지나도 못 찾으면 멈추고 `E|lost|돈 각도`를 보냅니다. Pi는 이걸 받거나 선이 10초(`LINE_LOST_S`) 안 보이면 멈춥니다. 값은 `main.py`의 `FOLLOW_*` · `CAM_*`. 걸음은 켤 때 `GAIT`(발 드는 시간 150 · 딛는 시간 500 · 다리 높이 40)로 맞춥니다(`G`로 바꿀 수 있음).
- 보폭은 50 이상으로 씁니다. 위에 부품을 얹은 상태에서 30은 제자리걸음만 하고, 50~70은 앞으로 갑니다(2026-11-26 실기).
- 확인: `T|100|line`으로 테이프를 좌우로 옮기며 `line` 값이 따라 바뀌는지 봅니다.

## 버전

보드는 `V`에 `dog-주.부.수+해시`로 답합니다 (예: `dog-1.1.0+a3f9c2`). 숫자는 `main.py`의 `VERSION`을 손으로 올리고, `+해시`는 `upload.py`가 올릴 때 붙입니다.

| 올리는 자리 | 언제 | 예 |
|---|---|---|
| 주 | Pi(`edge/`)도 같이 바꿔야 할 때. 명령·응답 형식, 채널 뜻·단위, 명령 삭제. `docs/protocol.md`도 함께 고침 | `F`의 값 순서를 바꿈, `line`을 0~1로 바꿈 |
| 부 | Pi는 그대로인데 로봇 움직임이나 할 수 있는 일이 바뀔 때. 새 명령·채널, 조향·안전 규칙 | 곡선 조향(1.1.0), 새 `R` 명령 |
| 수 | 움직임 규칙은 같고 고치거나 다듬을 때. 버그 수정, 값 조정, 주석 | `FOLLOW_FULL_PX` 40 → 30 |

- 위 자리를 올리면 아래 자리는 0으로 (1.1.3 → 1.2.0).
- `+해시`는 `main.py` 내용의 앞 6자리라 숫자를 깜빡해도 코드가 다르면 다르게 나옵니다. `python -m edge.hwcheck dog`가 보드 해시와 저장소 `main.py`가 같은지 알려 줍니다.
- `upload.py`는 올린 뒤 V 응답의 해시가 올린 코드와 다르면 실패로 끝납니다.

## 먼저 확인할 것

- 바닥 카메라로 선 따라가기와 색 마커를 함께 읽을 수 있는지 (지금은 펌웨어가 따로)
- MP3 모듈이 포트 2(주소 0x7B)에서 잡히는지, 1~2m에서 들리는지. `main.py`는 `Hiwonder_IIC.MP3`·`volume`·`playTrack` 이름으로 가정했으니 실제 이름으로 맞춥니다
- LED 화살표가 로봇 기준 방향과 맞는지 (LED는 `Hiwonder.Digitaltube`, IO32·IO33. `showNum`·`setBrightness`·`clear`·`drawStr(x, y, 글자)`·`setLedOnOff(x, y, 켜기)`. 지금은 `drawStr`로 `<` `>` `^` `X` 글자를 띄움)

# 관제 대시보드 · 이예은

관리자와 현장 작업자가 보는 웹 화면입니다. 서버(`server/api.py`)가 이 폴더를 그대로 내어 줍니다 (`index.html`이 있으면 `http://서버:8000/`).

"미정"은 다른 파트와 정하는 중인 것입니다. 정해지면 이 문서를 고칩니다.

## 화면

| 화면 | 보는 사람 | 내용 |
|---|---|---|
| 기본 화면 | 누구나 | 요약 줄(경보 4칸), 지도(구역, 화재 위치, 비상구, 대피 안내), 현재 모드, 안전 현황, 최근 경보, 연결 상태 |
| 관리자 화면 | 관리자 | 왼쪽 탭 두 개. 실시간 관제: 요약 줄(로봇 3칸 + 경보 4칸), 지도와 로봇 위치, 안전 현황, 로봇 현황, 최근 경보. 기록: 경보 이력, 안전모 미착용, 정탐률 |

- 기본 화면은 로그인 없이 누구나 봅니다. 관리자 화면은 비밀번호로 잠급니다 (아래 "관리자 잠금")
- 관리자 화면의 탭: 실시간 관제(지금 일)와 기록(지난 일). 팝업 · 경보음 · 대피 띠는 어느 탭을 보든 나옵니다. 실시간 관제 탭 옆 빨간 숫자는 해제 안 된 경보 수. 주소 끝 `#records`면 기록 탭으로 열립니다. 좁은 화면에서는 위쪽 가로 탭
- 기본 화면에는 로봇 현황과 경보 기록을 두지 않고, 대피 경로 안내는 둡니다. 로봇 상태·배터리는 작업자가 보고 할 일이 없고, 경보 기록은 사진에 사람이 찍힐 수 있어서입니다. 해제 안 된 경보는 최근 경보에, 로봇 연결은 위 막대에 나옵니다 (바꿀 수 있음)

## 화면 용어

화면에 쓰는 말입니다. 팀 문서·코드의 이름과 다른 것은 오른쪽에 적었습니다.

| 화면 용어 | 뜻 | 프로토콜·코드 |
|---|---|---|
| 경보 | 로봇이 감지해서 화면에 띄우는 것 하나하나 | `event` |
| 경보 해제 | 관리자가 현장 조치를 확인하고 누르는 것 | `POST /events/{id}/check` |
| 오탐 | 로봇이 잘못 본 경보. 관리자가 "오탐"으로 해제하면 서버에 오탐으로 기록 (나중에 모델 고칠 때 씀) | `POST /events/{id}/check` `{"false_alarm": true}` |
| 화재 | 관리자가 불꽃 감지 사진이나 현장을 보고 확정한 불. 대피 모드가 되면 화면도 화재로 봅니다 | `mode: evacuate` |
| 과열 | 45도 초과, 화재 의심 | `heat` |
| 불꽃 감지 | 로봇이 카메라로 불꽃을 본 것. 관리자가 팝업의 사진이나 현장을 보고 "화재 확정"을 누르면 화재(대피 모드)가 됩니다 | `flame` |
| 통로 차단 | 통로를 막은 물건 | `obstacle` |
| 밟힘 주의 | 바닥에 떨어진 낮은 물건 | `floor_object` |
| 충전 스테이션 | 로봇이 출발하고 충전하는 곳 (16번, 관리실) | 도크, `dock` |
| A 경로, B 경로 | 로봇이 순찰하는 길. A는 바깥 고리, B는 안쪽 길 포함 고리 | `role` |
| 구역 | 랙이 있는 칸 A1, A2, A3, B1, B2 | |
| 통로 구간 | 마커와 마커 사이 길. 예: 5–6번 통로 | |
| 대피 갈림길 1~4 | 대피 모드에서 로봇이 화살표로 비상구 방향을 가리키는 자리 | 갈림길 ①~④ |
| 교차 확인 | 과열을 감지하면 다른 로봇이 와서 다시 재는 것 (F-10) | |

로봇 이름: MD-1~MD-4 (팀 결정). 프로토콜 이름(ROBOT_ID)은 A~D 그대로이고, A 경로 · A1 구역과 헷갈리지 않게 화면에서만 MD-1(A) ~ MD-4(D)로 보여 줍니다.

## 안전 현황

| 단계 | 조건 |
|---|---|
| 안전 | 해제 안 된 경보가 없음 |
| 주의 | 해제 안 된 통로 차단, 밟힘 주의, 과열, 불꽃 감지, 로봇 연결 끊김 경보가 있음 |
| 화재 | 대피 모드 (서버가 화재를 확정함) |

경보 종류별 건수는 안전 현황 칸이 아니라 지도 위 요약 줄에 둡니다 (아래 "요약 줄").

## 요약 줄 (지도 위)

- 경보 4칸: 통로 차단, 밟힘 주의, 과열, 불꽃 감지의 해제 안 된 건수. 1건 이상이면 통로 차단 · 밟힘 주의는 주황, 과열 · 불꽃 감지는 빨강
- 경보 칸을 누르면 팝업. 1건이면 바로, 여러 건이면 칸 아래 목록(시각 · 위치 · 로봇)에서 골라서. 0건이면 누를 수 없음
- 로봇 3칸 (관리자 화면만): 4대를 나눠 담습니다
  - 충전 스테이션: 16번에서 대기. 충전 중인지는 서버가 알려 주지 않아 "충전 중"이라고 하지 않습니다
  - 확인 필요: 멈춤(아래 "로봇 현황") + 연결 끊김. 충전 스테이션에 있어도 멈춘 이유(`hold`)가 있으면 여기로 셉니다
  - 순찰 중: 나머지 (순찰, 출동, 복귀, 과열 확인, 막힘 정지, 대피 안내)
- 화재는 칸을 두지 않습니다. 대피 모드가 되면 맨 위 빨간 띠로 나옵니다

교차 확인은 하지 않기로 했습니다. 화재는 관리자가 불꽃 감지 팝업의 사진이나 현장을 보고 "화재 확정 (대피 모드)"를 눌러 정합니다. 화면은 대피 모드가 됐을 때만 화재라고 합니다.

## 경보

| 경보 | 로봇 동작 | 화면 알림 | 지도 표시 |
|---|---|---|---|
| 화재 (대피 모드) | 대피 안내 | 맨 위 빨간 띠 + 경보음 반복 ("경보음 멈춤"으로 끔) | 불난 마커 + 출구까지 대피 길 |
| 통로 차단 | 멈춤 | 팝업 + 경보음 | 팝업의 작은 지도에 마커 위치 |
| 과열 | 최대 60초 멈춰서 다시 잼 | 팝업 + 경보음 | 팝업의 작은 지도에 마커 위치 |
| 불꽃 감지 | 팝업에 "화재 확정 (대피 모드)" 버튼. 한 번 더 묻고 대피 모드로 | 팝업 + 경보음 (과열보다 높은 소리, 경보음을 꺼 둬도 남) | 팝업의 작은 지도에 마커 위치 |
| 밟힘 주의 (Should, 필수 아님) | 안 멈춤 | 팝업 + 경보음 | 팝업의 작은 지도에 마커 위치 |
| 로봇 연결 끊김 | | 위 알림 줄, 요약 줄 "확인 필요" | 마지막 위치 (회색 점선) |
| 사람 호출 (서버 `link_alert`, 이슈 #39) | | 위 주황 띠 "사람 호출 MD-2 연결 끊김, 마커 1로 가 주세요" (두 화면), 관리자 화면은 경보음 2번(440Hz), 로봇 카드 "사람 호출 중" | |
| 안전모 미착용 | 음성 안내 | 팝업 · 경보음 없음. 기록 탭 "안전모 미착용" 칸에 기록, 누르면 사진 | 누르면 팝업의 작은 지도에 위치 |

- 팝업 (관리자 화면): 사진(누르면 크게), 위치를 표시한 작은 지도, 값(날짜와 시각, 감지한 로봇, 경로, 위치, 신뢰도, 온도(과열 · 불꽃 감지), 사람 여부(통로 차단)), 경보 해제 · 오탐 버튼
  - 새 경보가 오면 저절로 뜹니다. 여러 건이면 차례로 ("대기 중인 팝업 n건")
  - 닫은 뒤에는 요약 줄 경보 칸이나 최근 경보를 눌러 다시 봅니다. 기록 탭의 경보 이력 시각을 눌러도 팝업 (해제된 경보는 버튼 없이 "경보 해제" / "오탐으로 해제")
  - 경보 해제나 오탐을 보내면 팝업이 닫힙니다
- 팝업 (기본 화면): 누를 때만. 위치 지도와 위치 글만 (사진 · 값 · 버튼 없음). 새 경보에 저절로 뜨지 않고 소리도 없습니다
- 경보 상세 칸은 없앴습니다 (팝업으로 다시 보기 때문). 최근 경보는 깜빡이지 않습니다 (요약 줄 색과 팝업으로 충분)

경보음 (관리자 화면, "경보음 켜기"를 누른 뒤. 불꽃 감지와 대피 소리는 꺼 둬도 남):

| 경보 | 소리 |
|---|---|
| 대피 모드 (화재 확정) | 높은 삐 3번 (880Hz), 3초마다 반복. 경보음을 꺼 둬도 남 ("경보음 멈춤"으로만 멈춤) |
| 불꽃 감지 | 삐 2번 (784Hz). 경보음을 꺼 둬도 남 |
| 통로 차단 | 삐 2번 (660Hz) |
| 과열, 밟힘 주의 | 낮은 삐 1번 (520Hz) |
- 통로 차단도 다른 경보처럼 "해제 전 → 경보 해제" 두 상태입니다. 로봇은 물건이 치워지면 초음파로 알아서 다시 출발하고(F-09, `edge/agent.py`), 경보 해제는 로봇 동작과 상관없이 경보만 닫습니다 (`server/api.py`)
- 화재를 끝내는 것은 대피 해제입니다. 누르기 전에 화면 안에서 한 번 더 확인합니다. 불꽃 감지 경보는 다른 경보처럼 바로 해제합니다. 화재로 확정하려면 불꽃 감지 팝업의 "화재 확정 (대피 모드)"를 누릅니다 (`POST /mode {"mode": "evacuate", "fire": 마커}`).
- 기본 화면에는 경보 해제 버튼이 없습니다.
- 과열의 경보 해제를 누가 하는지: 미정

## 로봇 현황 (관리자 화면)

- 상태: 대기, 순찰(A 경로 / B 경로), 막힘 정지, 과열 확인, 출동, 대피 안내, 복귀
- 멈춤: "대기"인데 state에 멈춘 이유(`hold`)가 있거나, 충전 스테이션이 아닌 곳에 있는 로봇 (이슈 #22). 카드는 주황 테두리와 "멈춤", 지도는 주황 테두리. 안전 현황 단계는 올리지 않습니다
  - 서버 대기(`hold`가 `wait`): 서버가 길이 빌 때까지(교통 정리, server PR #35) 또는 교차 확인 동안 세운 것. 멈춤으로 보지 않고 카드에 "서버 대기", 요약 줄은 순찰 중으로 셉니다. 서버가 다시 출발시킵니다
  - 서버는 `hold`가 있는 로봇을 자동 출발시키지 않습니다 (server/fleet.py). 그래서 충전 스테이션에 있어도 `hold`가 있으면 멈춤으로 보여 줘야 관리자가 왜 안 나가는지 압니다
  - 멈춘 로봇 카드에 "다시 출발" 버튼: 관리자가 현장을 확인하고 누르면 서버에 resume을 보내 `hold`를 풉니다. 서버 대기(`wait`)는 멈춤이 아니라 버튼이 없고, 배터리 부족 정지(`battery`)는 충전이 먼저라 버튼이 없고, 대피 안내(`guide`)는 대피가 끝나면 서버가 풉니다
  - `hold` 값(edge/agent.py: wait, stop, guide, link, stream, no_ack, board, send, line, not_ready, exit, server, battery)은 "안전 정지: 선을 놓침" 같은 말로 보여 줍니다 (js/store.js HOLD_TEXT). `hold`가 없으면 "현장 확인 필요"
- 배터리: 25% 이하면 충전 스테이션으로 복귀, 15% 이하면 그 자리에 멈춤 (`server/map_config.py`, 시험 뒤 바뀔 수 있음)
- 프로그램 버전: 로봇마다 돌고 있는 Pi 프로그램의 git 커밋

## 관리자 잠금

- 서버 저장소 맨 위 `.env`에 `ADMIN_PASSWORD=...`를 적으면 서버가 잠급니다 (`server/api.py`, PR #23). 비워 두면 잠그지 않습니다
- `?admin`으로 열면 먼저 `GET /admin/check`로 묻고, 잠겨 있으면 비밀번호 칸을 띄웁니다. 맞을 때까지 관리자 화면을 열지 않습니다
- 비밀번호는 이 탭에만 둡니다 (sessionStorage). 탭을 닫으면 다시 묻습니다
- 경보 해제, 대피 해제는 헤더 `X-Admin-Password`를 붙여 보냅니다. 401이 오면 비밀번호가 바뀐 것으로 보고 다시 묻습니다
- 보기(WebSocket, 사진, 기본 화면)는 서버가 잠그지 않습니다

## 관리자 버튼

| 버튼 | 상태 | 서버 |
|---|---|---|
| 경보 해제 | 넣음. 팝업에 | `POST /events/{id}/check` (body 없음 = 정탐) |
| 오탐 | 넣음. 경보 해제 옆. 경보 이력에 "오탐으로 해제"로 남음 | `POST /events/{id}/check` `{"false_alarm": true}` |
| 대피 해제 | 넣음. 누르기 전에 한 번 더 확인 | `POST /mode` `{"mode": "normal"}` |
| 출발 | 넣지 않음. 서버가 자동으로 내보냄 (PR #23). 대피가 끝나면 대피 안내로 세운 로봇도 서버가 다시 출발시킴 (PR #31) | |
| 다시 출발 | 넣음. 멈춘 로봇 카드에 (관리자 stop, 안전 정지 등). 서버 대기(wait)에는 없음 | `POST /robots/{로봇}/cmd` `{"cmd": "resume"}` |
| 교차 확인 요청 | 넣지 않음. 교차 확인은 하지 않기로 함 | |
| 화재 확정 | 넣음. 불꽃 감지 팝업에만, 한 번 더 묻고 대피 모드로 | `POST /mode` `{"mode": "evacuate", "fire": 마커}` (`fire`는 서버에 받아 달라고 부탁) |

## 서버와 주고받기

- 받음: WebSocket `/ws`. 붙자마자 지금 상태(로봇 state 전부, mode, 해제 안 된 경보)를 받고, 그 뒤로 새 메시지를 받습니다 ([docs/protocol.md](../docs/protocol.md) 3절)
  - `{"kind": "state", "robot": "A", "role": "A", "online": true, …}`
  - `{"kind": "event", "id": 12, "robot": "B", "type": "obstacle", "checked": false, …}`. 해제되면 같은 id가 `"checked": true`로 다시 옴
  - `{"kind": "mode", "mode": "evacuate"}`. 관리자가 화재를 확정하면(또는 서버가) 보냄
  - `{"kind": "evac", "fire": 6, "exits": [5, 9], "arrows": [{"marker": 3, "dir": "E", "exit": 9, "path": [3, 4, 9]}, …]}`. 대피가 되면 `mode` 다음에 옴 (`server/dispatch.py`, PR #23)
    - `fire`: 불난 마커. 관리자가 직접 대피로 바꾸면 `null`
    - `arrows`: 마커 1~16마다 하나. `dir`은 지도 기준 N·E·S·W, 출구면 `here`, 갈 수 없거나 불난 마커면 `x`
    - 평상시로 돌아가면 따로 알리지 않음. `mode`가 `normal`이면 화면이 지움
- 사진: `GET /photos/{이름}`
- 지난 경보: `GET /events?limit=500&before=id` (PR #23). 닫힌 경보까지 최근 것부터, `checked_at`(해제 시각), `false_alarm`
  - 관리자 화면을 열 때와 서버에 다시 붙을 때 첫 500건을 받습니다. 경보 이력은 위의 종류 버튼(전체, 통로 차단, 밟힘 주의, 과열, 불꽃 감지, 버튼마다 건수)으로 거르고, 표는 10줄 높이로 고정해 10건씩 쪽 번호로 넘깁니다. 받은 것의 마지막 쪽에서 서버에 더 있으면 "이전 기록 더 받기"로 그 앞 500건을 더 받습니다
  - 안전모 미착용 기록도 10건씩 쪽 번호로 넘깁니다
  - GET /events가 없는 예전 서버(404)면 이 화면을 연 뒤 받은 경보만 보여 줍니다

## 안전모 미착용 기록 (관리자 화면)

- 팀 결정 (11/27 회의): 현장에서는 음성 안내, 대시보드는 사진까지 기록으로 받아 둠. 팝업은 띄우지 않고 필요하면 들어가서 확인
- 기록 탭 오른쪽 "안전모 미착용" 칸: 오늘 건수, 받아 온 기록 건수, 자주 나온 위치(상위 3곳), 최근 10건(시각 · 위치 · 로봇 · 사진 여부)
- 줄을 누르면 팝업: 사진(누르면 크게), 위치 지도, 값. 경보 해제 · 오탐 버튼은 없음 (현장에서 음성으로 처리하므로)
- 새 안전모 경보에 팝업 · 경보음이 없고, 최근 경보 · 경보 이력 · 요약 줄 · 안전 현황 · 정탐률에도 넣지 않습니다
- 칸을 빼려면 `js/app.js`의 `SHOW_HELMET`을 `false`로

## 정탐률

- 관리자 화면 기록 탭 오른쪽, 작은 글씨 (참고용). 해제한 경보 중 실제였던 비율 = (해제한 경보 − 오탐) ÷ 해제한 경보. 전체와 통로 차단 · 밟힘 주의 · 과열 · 불꽃 감지별
- "정확도"라고 하지 않습니다. 로봇이 놓친 위험은 경보가 없어서 셀 수 없기 때문입니다
- 화면이 받아 온 경보 이력만 셉니다 (처음 500건, "이전 기록 더 받기"로 늘어남). 기간별(오늘, 이번 주)이나 전체 기록 기준으로 보려면 서버에 집계 요청(예: `GET /events/stats?since=`)을 따로 부탁해야 합니다
- 안전모 미착용은 경보 해제를 하지 않으므로 뺍니다

## 개발

- 서버 없이: 가짜 서버 [js/fake.js](js/fake.js)가 진짜 서버와 같은 모양으로 메시지를 흘려 줍니다.
  - 저장소 폴더(`physical-ai-safety-patrol`)에서 `python -m http.server 8080 -d dashboard`를 켜고 `http://localhost:8080/fake.html`을 엽니다 (파일을 바로 열면 JS 모듈이 안 불러와집니다)
  - 경보 보내기, 화재와 대피를 버튼으로 해 볼 수 있습니다
  - 화재 위치와 대피 안내: `http://localhost:8080/?fake`(또는 `?fake&admin`)를 열고 브라우저 콘솔에서 `fake.fire("A", 7)`. 로봇이 과열 · 불꽃 감지를 보내고 서버가 7번 화재로 대피 모드로 바꾼 것처럼 `mode`와 `evac`을 보냅니다. 마커를 빼면 그 로봇이 있는 마커. 대피 경로는 `server/dispatch.py`를 옮긴 `evacPlan()`으로 셉니다
  - 길 중간에 멈춘 로봇: 콘솔에서 `fake.halt("A")`(이유 없이) 또는 `fake.halt("A", "line")`, 다시 순찰은 `fake.resume("A")`
  - 지난 경보와 정탐률: `http://localhost:8080/?fake&admin&past`로 열면 가짜 서버에 지난 경보 40건(닫힘, 일부 오탐)을 넣어 둡니다
  - 관리자 잠금: `http://localhost:8080/?fake&admin&lock`으로 열면 가짜 서버도 잠깁니다. 비밀번호는 `1234`. 콘솔에서 `fake.adminPassword = "5678"`로 바꾸면 비밀번호가 바뀐 경우를 볼 수 있습니다
  - 진짜 서버는 끊긴 로봇의 state를 더 보내지 않습니다. 로봇 연결 끊김은 화면이 마지막 state를 받은 시각으로 판단해야 합니다 (7초, `store.js` `ONLINE_SEC` = `server/fleet.py`)
  - 사람 호출 (이슈 #39): 로봇이 서버와 끊기면 단독 모드로 다음 마커까지 가서 멈춥니다(`hold: "server"`, 카드에 "서버 연결 끊김으로 정지"). 서버가 `{"kind": "link_alert", "robot", "marker", "stop_marker", "online", "active"}`를 보내면 `active`가 true일 때 띠를 띄우고 false면 내립니다. 갈 곳은 `stop_marker`, 모르면 `marker`. state의 `call_human`이 true면 로봇 카드에 "사람 호출 중", false면 띠도 내립니다 (대시보드가 끊긴 사이에 풀렸거나 서버가 다시 켜져 `active:false`를 못 받은 경우)
  - 가짜 서버: 콘솔에서 `fake.linkLost("B", 1)`(B가 끊겨 1번에서 멈춤), 내리기는 `fake.linkBack("B")`
- 셀프 체크: `node dashboard/selfcheck.mjs`. 지도 데이터 [js/mapdata.js](js/mapdata.js)가 `server/map_config.py`와 같은지, 가짜 서버가 진짜 서버와 같은 순서·모양으로 보내는지 봅니다. CI가 `check.sh`로 돌립니다
- 서버와 같이: `python -m server.fake_robots`와 `python -m server.api`를 켜고 브라우저로 엽니다
  - 노트북의 Mosquitto(포트 1883)가 켜져 있어야 합니다
  - 저장소 루트 `.env`에 현장 브로커 주소(`MQTT_HOST=192.168.0.10` 등)가 있으면 서버는 그쪽으로 붙고, 가짜 로봇은 `localhost`로 붙어서 서로 못 만납니다. 화면에 로봇이 전부 "수신 기록 없음"으로 나옵니다. 가짜 로봇과 시험할 때는 `MQTT_HOST=localhost python -m server.api`로 켭니다 (PowerShell은 `$env:MQTT_HOST="localhost"; python -m server.api`)
- 브라우저는 화면을 한 번 누르기 전에는 소리를 막습니다. 관리자 화면에 "경보음 켜기" 버튼을 둡니다.
- 불꽃 감지와 대피 소리는 경보음을 꺼 둬도 납니다. 다만 화면을 연 뒤 한 번이라도 누르거나 키를 쳐야(관리자 비밀번호 입력 포함) 브라우저가 소리를 허락합니다.
- 경보는 2초 안에 화면에 떠야 합니다.

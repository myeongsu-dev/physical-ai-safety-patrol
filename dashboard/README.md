# 관제 대시보드 · 이예은

관리자와 현장 작업자가 보는 웹 화면입니다. 서버(`server/api.py`)가 이 폴더를 그대로 내어 줍니다 (`index.html`이 있으면 `http://서버:8000/`).

"미정"은 다른 파트와 정하는 중인 것입니다. 정해지면 이 문서를 고칩니다.

## 화면

| 화면 | 보는 사람 | 내용 |
|---|---|---|
| 기본 화면 | 누구나 | 지도(구역, 화재·통로 차단 위치, 비상구), 현재 모드, 안전 현황, 연결 상태 |
| 관리자 화면 | 관리자 | 기본 화면 + 로봇 위치와 현황, 경보 팝업과 사진, 경보 해제, 경보 기록, 관리자 버튼 |

- 기본 화면을 로그인 없이 따로 둘지, 관리자 화면을 어떻게 잠글지: 미정
- 기본 화면에는 로봇 현황과 경보 기록을 두지 않고, 대피 경로 안내는 둡니다. 로봇 상태·배터리는 작업자가 보고 할 일이 없고, 경보 기록은 사진에 사람이 찍힐 수 있고 화면을 연 뒤 받은 것만 보여서입니다. 해제 안 된 경보는 최근 경보에, 로봇 연결은 위 막대에 나옵니다 (바꿀 수 있음)

## 화면 용어

화면에 쓰는 말입니다. 팀 문서·코드의 이름과 다른 것은 오른쪽에 적었습니다.

| 화면 용어 | 뜻 | 프로토콜·코드 |
|---|---|---|
| 경보 | 로봇이 감지해서 화면에 띄우는 것 하나하나 | `event` |
| 경보 해제 | 관리자가 현장 조치를 확인하고 누르는 것 | `POST /events/{id}/check` |
| 화재 | 서버가 교차 확인으로 확정한 불. 서버가 대피 모드로 바꾸면 화면도 화재로 봅니다 | `mode: evacuate` |
| 과열 | 45도 초과, 화재 의심 | `heat` |
| 불꽃 감지 | 과열을 다시 재던 로봇 한 대가 카메라로 불꽃도 본 것. 서버가 아직 확인하는 중이라 화재가 아닙니다 | `flame` |
| 통로 차단 | 통로를 막은 물건 | `obstacle` |
| 밟힘 주의 | 바닥에 떨어진 낮은 물건 | `floor_object` |
| 충전 스테이션 | 로봇이 출발하고 충전하는 곳 (15번, 관리실) | 도크, `dock` |
| A 경로, B 경로 | 로봇이 순찰하는 길. A는 바깥 고리, B는 안쪽 길 포함 고리 | `role` |
| 구역 | 랙이 있는 칸 A1, A2, A3, B1, B2 | |
| 통로 구간 | 마커와 마커 사이 길. 예: 5–6번 통로 | |
| 대피 갈림길 1~4 | 대피 모드에서 로봇이 화살표로 비상구 방향을 가리키는 자리 | 갈림길 ①~④ |
| 교차 확인 | 과열을 감지하면 다른 로봇이 와서 다시 재는 것 (F-10) | |

로봇 이름: 미정 (팀 상의 중). 프로토콜 이름은 A~D인데 A 경로, A1 구역과 헷갈려서 화면 이름을 따로 둘지 정합니다.

## 안전 현황

| 단계 | 조건 |
|---|---|
| 안전 | 해제 안 된 경보가 없음 |
| 주의 | 해제 안 된 통로 차단, 밟힘 주의, 과열, 불꽃 감지, 로봇 연결 끊김 경보가 있음 |
| 화재 | 대피 모드 (서버가 화재를 확정함) |

같이 보여줄 건수: 과열·불꽃 감지, 통로 차단, 밟힘 주의.

화면은 서버보다 먼저 화재라고 하지 않습니다. 화재는 서버가 교차 확인(`server/events.py`)으로 정하고, 화면은 그 결과(대피 모드)만 보여 줍니다.

## 경보

| 경보 | 로봇 동작 | 화면 알림 | 지도 표시 |
|---|---|---|---|
| 화재 (대피 모드) | 대피 안내 | 맨 위 빨간 띠 + 경보음 반복 ("경보음 멈춤"으로 끔) | 통로 구간 + 양옆 의심 구역 |
| 통로 차단 | 멈춤 | 팝업 + 경보음 | 마커 위치. 다른 로봇 경로 위에도 표시 |
| 과열 | 최대 60초 멈춰서 다시 잼 | 오른쪽 칸 + 깜빡임 + 경보음 | 통로 구간 |
| 불꽃 감지 | 과열과 같음 (서버가 교차 확인) | 오른쪽 칸 + 깜빡임 + 경보음 | 마커 위치 |
| 밟힘 주의 (Should, 필수 아님) | 안 멈춤 | 오른쪽 칸 + 깜빡임 + 경보음 | 마커 위치 |
| 로봇 연결 끊김 | | 오른쪽 칸 | 마지막 위치 |
| 안전모 미착용 | 음성 안내 | 미정 | 미정 |

- 팝업: 사진, 위치를 표시한 작은 지도, 위치 정보(통로 구간, 마커 번호, 구역), 경보 해제 버튼
- 오른쪽 경보 상세 칸: 늘 보입니다. 팝업을 닫은 뒤에도 사진과 내용을 다시 보고, 여기서도 경보 해제합니다.
- 경보에 보여줄 값: 사진(누르면 크게), 날짜와 시각, 감지한 로봇, 위치, 신뢰도, 온도(과열·불꽃 감지), 사람 여부(통로 차단)
- 통로 차단도 다른 경보처럼 "해제 전 → 경보 해제" 두 상태입니다. 로봇은 물건이 치워지면 초음파로 알아서 다시 출발하고(F-09, `edge/agent.py`), 경보 해제는 로봇 동작과 상관없이 경보만 닫습니다 (`server/api.py`)
- 화재를 끝내는 것은 대피 해제입니다. 누르기 전에 화면 안에서 한 번 더 확인합니다. 불꽃 감지 경보는 다른 경보처럼 바로 해제합니다.
- 기본 화면에는 경보 해제 버튼이 없습니다.
- 과열의 경보 해제를 누가 하는지: 미정

## 로봇 현황 (관리자 화면)

- 상태: 대기, 순찰(A 경로 / B 경로), 막힘 정지, 과열 확인, 출동, 대피 안내, 복귀
- 배터리: 25% 이하면 충전 스테이션으로 복귀, 15% 이하면 그 자리에 멈춤 (`server/map_config.py`, 시험 뒤 바뀔 수 있음)
- 프로그램 버전: 로봇마다 돌고 있는 Pi 프로그램의 git 커밋

## 지도

- 미션맵 배치 그대로, 코너는 직각, QR 대신 마커 번호 1~15. 마커 좌표는 `server/map_config.py`
- 바탕: 03 미션맵 시뮬레이션 지도(`physical-ai-corp-project`의 `assets/sim/missionmap.js`)를 가져와 다듬어 씁니다.
- 화재 위치: 서버가 계산한 통로 구간을 빨갛게, 양옆 구역을 "화재 의심"으로 표시. 구역이 하나로 정해지면 그 구역만 남김
- 대피 모드: 대피 갈림길 1~4에 비상구 방향 화살표 (방향은 서버가 계산)

## 관리자 버튼

| 버튼 | 상태 | 서버 |
|---|---|---|
| 경보 해제 | 넣음 | `POST /events/{id}/check` |
| 대피 해제 | 넣음. 누르기 전에 한 번 더 확인 | `POST /mode` `{"mode": "normal"}` |
| 출발 | 미정 (사람이 누를지, 서버가 알아서 내보낼지) | `POST /fleet/start`, `POST /robots/{로봇}/patrol?role=A` |
| 교차 확인 요청 | 넣지 않음. 교차 확인 명령은 서버가 내림 | |

## 서버와 주고받기

- 받음: WebSocket `/ws`. 붙자마자 지금 상태(로봇 state 전부, mode, 해제 안 된 경보)를 받고, 그 뒤로 새 메시지를 받습니다 ([docs/protocol.md](../docs/protocol.md) 3절)
  - `{"kind": "state", "robot": "A", "role": "A", "online": true, …}`
  - `{"kind": "event", "id": 12, "robot": "B", "type": "obstacle", "checked": false, …}`. 해제되면 같은 id가 `"checked": true`로 다시 옴
  - `{"kind": "mode", "mode": "evacuate"}`. 서버가 교차 확인으로 화재를 확정하면 보냄
- 사진: `GET /photos/{이름}`
- 아직 서버에 없어서 정하는 중: 화재 위치(통로 구간과 의심 구역), 대피 갈림길 방향, 지난 경보 목록
  - 화재 위치와 대피 화살표는 대시보드가 아래 모양(제안)으로 받을 준비가 돼 있습니다. 둘 다 서버가 화재를 확정한 뒤의 대피 `mode` 메시지에 붙입니다. 서버가 보내지 않으면 지도에 그리지 않습니다. 서버와 정해지면 이 모양을 고칩니다
    - `"fire": {"segment": [5, 6], "zones": ["A1", "B1"]}`. `segment`는 불이 난 통로(이웃한 마커 두 개), `zones`는 양옆 의심 구역. 좁혀지면 대피 `mode` 메시지를 다시
    - `"guides": [{"marker": 7, "dir": "E", "exit": 2, "path": [7, 8]}]`. `dir`은 지도 기준 N·E·S·W, `path`는 비상구까지 지나는 마커 (없어도 됨)
  - 경보 이력(관리자 화면)은 지난 경보 목록 요청이 없어서 화면을 연 뒤에 받은 경보만 보여 줍니다. 해제 시각은 보여 주지 않고 "해제 전 / 경보 해제"만 표시합니다

## 개발

- 서버 없이: 가짜 서버 [js/fake.js](js/fake.js)가 진짜 서버와 같은 모양으로 메시지를 흘려 줍니다.
  - 저장소 폴더(`physical-ai-safety-patrol`)에서 `python -m http.server 8080 -d dashboard`를 켜고 `http://localhost:8080/fake.html`을 엽니다 (파일을 바로 열면 JS 모듈이 안 불러와집니다)
  - 경보 보내기, 화재와 대피를 버튼으로 해 볼 수 있습니다
  - 화재 위치와 대피 화살표: `http://localhost:8080/?fake`(또는 `?fake&admin`)를 열고 브라우저 콘솔에서 `fake.fire("A", true)`. 로봇이 과열·불꽃 감지를 보내고 서버가 대피 모드로 바꾼 것처럼, 대피 메시지에 예시 값(5–6번 통로, A1·B1, 비상구 2로 안내)을 붙여 보냅니다
  - 진짜 서버는 끊긴 로봇의 state를 더 보내지 않습니다. 로봇 연결 끊김은 화면이 마지막 state를 받은 시각으로 판단해야 합니다
- 셀프 체크: `node dashboard/selfcheck.mjs`. 지도 데이터 [js/mapdata.js](js/mapdata.js)가 `server/map_config.py`와 같은지, 가짜 서버가 진짜 서버와 같은 순서·모양으로 보내는지 봅니다. CI가 `check.sh`로 돌립니다
- 서버와 같이: `python -m server.fake_robots`와 `python -m server.api`를 켜고 브라우저로 엽니다
  - 노트북의 Mosquitto(포트 1883)가 켜져 있어야 합니다
  - 저장소 루트 `.env`에 현장 브로커 주소(`MQTT_HOST=192.168.0.10` 등)가 있으면 서버는 그쪽으로 붙고, 가짜 로봇은 `localhost`로 붙어서 서로 못 만납니다. 화면에 로봇이 전부 "수신 기록 없음"으로 나옵니다. 가짜 로봇과 시험할 때는 `MQTT_HOST=localhost python -m server.api`로 켭니다 (PowerShell은 `$env:MQTT_HOST="localhost"; python -m server.api`)
- 브라우저는 화면을 한 번 누르기 전에는 소리를 막습니다. 관리자 화면에 "경보음 켜기" 버튼을 둡니다.
- 경보는 2초 안에 화면에 떠야 합니다.
- 시간이 되면(Could): 모바일 알림 앱 시안
